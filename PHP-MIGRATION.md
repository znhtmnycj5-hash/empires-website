# Clanwars: переход на PHP + MySQL

Рабочая ветка: `php-migration`. Ветка `main` и текущий сайт не изменяются.

## Что уже добавлено

- `includes/database.php` — PDO-подключение к MySQL/MariaDB.
- `includes/http.php` — JSON-ответы, разбор JSON-запросов и CSRF.
- `includes/auth.php` — PHP-сессии и получение текущего пользователя.
- `api/php-auth.php` — API: `me`, `check_name`, `register`, `login`, `logout`, `profile_update`.
- `assets/php-auth.js` — клиентская обёртка для нового API.
- `config/database.example.php` — пример локальной конфигурации без паролей.

## Важно: пока не подключать к страницам

Существующие модули сайта обращаются не только к авторизации, но и напрямую к Supabase Query Builder, Storage и RPC. В частности, форум, чат, полки, рейтинги, уведомления и административные разделы используют эти интерфейсы.

Поэтому нельзя просто заменить подключение `assets/supabase-auth.js` на `assets/php-auth.js`: поле `EMPIRE_AUTH.client` у нового клиента намеренно равно `null`, пока соответствующие API этих модулей не перенесены. Старые HTML-файлы и Supabase-подключения на этом этапе оставлены без изменений.

## Настройка для отдельного тестового развёртывания

1. Скопировать `config/database.example.php` в `config/database.local.php`.
2. Указать параметры отдельной тестовой базы. Не добавлять этот файл в Git.
3. Убедиться, что PHP имеет расширения `pdo_mysql`, `mbstring` и включённые сессии.
4. Развернуть только в отдельном тестовом каталоге, не поверх работающего сайта.
5. Проверить GET-запрос `/api/php-auth.php?action=me`. Он должен вернуть JSON с `success: true` и CSRF-токеном.

## Ожидаемая структура таблиц

API рассчитан на таблицы `users` и `user_profiles`, которые уже есть в текущей MySQL-основе проекта:

- `users`: `id`, `email`, `password_hash`, `status`, `created_at`, `updated_at`, `last_login_at`.
- `user_profiles`: `user_id`, `display_name`, `regiment_name`, `avatar_url`, `bio`, `last_seen_at`, `created_at`, `updated_at`.

Для корректной защиты от одновременной регистрации одинаковых адресов поле `users.email` должно иметь UNIQUE-индекс. Перед добавлением индекса на существующей базе сначала проверить дубликаты; автоматически менять действующую базу этим этапом нельзя. Уникальный индекс на `user_profiles.display_name` должен быть регистронезависимым (например, collation `utf8mb4_unicode_ci`).

## Что ещё не перенесено

- Письма подтверждения адреса и восстановление пароля.
- Загрузка/удаление аватаров на сервере.
- Удаление аккаунта.
- Полноценный адаптер данных для всех старых модулей.
- Полки, союзы, чат, форум, новости, комментарии, уведомления, рейтинги, бои, кампании, артиллерия, поиск и админка.

Наличие этих файлов не означает, что весь сайт уже переведён на PHP. Миграция будет выполняться модуль за модулем с проверкой совместимости, без удаления исходников Supabase до завершения перехода.
